# Design: Clawdipedia Navigation

## The Problem, Measured

The sidebar is autogenerated. `sidebars.ts` holds one entry,
`{ type: "autogenerated", dirName: "." }`, so the sidebar is the folder tree plus each
`_category_.json`. A folder with many pages becomes a long flat list.

Page counts per folder, from `find docs -type f`:

| Folder | Pages | Reader's problem |
| --- | --- | --- |
| `docs/prompts/` | 95 | One list of 95 entries. No way to see the kinds. |
| `docs/extend/mod-api/` | 16, plus 11 under `types/` | One list of 16, then a second of 11. |
| `docs/configure/env-vars/` | 16 | Already grouped by topic in the file names. Readable. |
| `docs/configure/settings/` | 10 | Readable. |
| `docs/how-it-works/` | 10 | Readable. |

So two folders need groups, `prompts/` and `mod-api/`. The rest need a better entry point, not a
different tree.

## Decision 1: Group by the Reader's Question, Not by the Capture Tool

The prompts section already has seven variant arrays in `tools/capture-prompts/variants/`, and they
almost match the groups a reader wants. The groups become a field on `Variant`, not a folder scan,
because a field fails the type check when a new variant has no group, and a folder scan fails silently.

Ten groups, in sidebar order:

| Group | Folder | What a reader asks |
| --- | --- | --- |
| Defaults | `defaults/` | What does the model read when I change nothing? |
| Output Styles | `output-styles/` | What does an output style add or remove? |
| Context and Memory | `context-and-memory/` | What does compaction or a memory file change? |
| Agents | `agents/` | What does a subagent read? |
| Commands | `commands/` | What does a built-in command send? |
| Hooks | `hooks/` | What does a prompt hook send? |
| Modes | `modes/` | What does a permission mode add? |
| Skills | `skills/` | What is the text of a built-in skill? |
| Tools | `tools/` | Which tools go with which variant? |
| Other | `other/` | Everything else. |

`index.md` stays at `docs/prompts/index.md` and keeps `sidebar_position: 1`, so the section still has
one landing page with the full table.

## Decision 2: One Link Helper, Not Hand-Written `../`

With groups, a link between two pages crosses a folder. The renderer writes four kinds of link: a
duplicate page, a baseline diff, the tools page, and the index rows. Each one needs the right number of
`../`. One helper takes the source group and the target id and returns the link. Hand-written `../`
in four places goes stale the first time a page moves group.

## Decision 3: `mod-api` Groups Follow the Mod API's Own Nouns

| Group | Pages |
| --- | --- |
| (top level) | `index.md`, `nouns-and-gates.md` |
| Session and Turn | `session.md`, `turn-prompt.md`, `agent.md`, `plugin.md` |
| Tools and Events | `tool-command-config.md`, `hooks.md`, `classic-events.md` |
| User Interface | `ui.md`, `ui-elements.md`, `ui-events.md` |
| Platform | `clock-http-process-env-settings.md`, `fs-store-state.md`, `model-audio-mcp.md`, `telemetry.md`, `testing.md` |
| Types | the 11 pages already under `types/` |

`nouns-and-gates.md` stays beside the index, because a reader needs it before any group.

Two page names each carry more than one noun: `clock-http-process-env-settings.md` and
`model-audio-mcp.md`. A name that lists four nouns tells a reader nothing, so each one is a candidate
to split into one page per noun. That split is not in this change, because it changes every anchor that
links into those pages. It is recorded here as the next step.

## Decision 4: The Landing Page Answers Questions

`docs/index.mdx` currently has a "Map of the Site" table whose rows are sections. A reader does not
arrive with a section in mind. The table becomes a question in the left column and its page in the
right column, and the section map moves below it.

Each `_category_.json` gets a `link` of type `generated-index` with a `description`, so every group has
a page that lists its children. Four of the nine category files already have one.

## Decision 5: The Language Rewrite Never Touches Evidence

Three kinds of text keep their exact bytes:

1. Every fenced block in `docs/prompts/`, because it is program text that a probe captured.
2. Every generated table, such as the rows on `docs/reference/surface-coverage.md`.
3. Every quoted program string anywhere, such as an error text.

The rewrite applies to prose: a paragraph, a list item that is not a captured line, an admonition, and
a table cell that a person wrote.

The linter is
`/Users/krystian/.claude/plugins/cache/asd-ste100-skill-next/asd-ste100/0.5.0/skills/rewrite/scripts/ste-lint`.
It reports `hard` and `advisory` findings and takes `--json`. Zero findings does not prove compliance,
because the linter checks structure only. So each page also needs a read for one instruction per
sentence, noun clusters of at most three words, and one term per concept.
